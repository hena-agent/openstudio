# 스튜디오 제작 시스템

## 제품 목표

에이전트와 사용자가 제작 과정을 함께 구성하고, 스텝별 검수·피드백·수정을 거쳐 여러 결과물을 완성한다. 특정 주제나 고정 제작 순서를 강제하지 않는다.

프로젝트는 공통 설정과 재사용할 스텝 구성의 원본이며 **한 제작 세션이 영상 한 편**이다. 같은 영상의 세로·가로·축약본·자막 등은 제작 스텝의 결과이며 별도 에피소드 묶음이 아니다. 브랜드 수립·채널 개설·월간 편성·다주차 운영·여러 편 동시 제작·주간 성과 분석은 기본 제작 스텝에 포함하지 않는다.

- 에이전트가 스텝과 출력 분기를 제안하고 사용자가 직접 추가·삭제·순서·입력 연결·모델을 편집한다.
- 이미지 기반 영상, 직접 영상 모델, SVG/HTML 코드, 기존 에셋 편집 등의 제작 방식을 조합한다.
- 자동 진행과 사용자 검수를 스텝마다 선택한다. 승인한 결과 버전만 다음 스텝 입력으로 전달한다.
- 입력 변경에 영향을 받는 후속 결과를 갱신 필요로 표시하고 필요한 스텝만 다시 준비·실행한다.
- 공통 원고와 장면에서 세로/가로 영상·티저·썸네일·자막 등 여러 출력으로 분기한다.

## 현재 구현: 제작 준비 MVP

이번 범위는 영상 파일을 생성하지 않고 실제 제작에 필요한 계획과 결과를 준비하는 것이다.

1. 제작 프로젝트 생성·SQLite 저장
2. 선택한 텍스트 계정·모델로 Pi 에이전트의 계획 제안 요청
3. 제안 검토 후 적용 또는 직접 스텝 추가·삭제·이동·입력 연결 편집
4. 원고·장면/이미지/영상/음성/합성/출력 명세·SVG/HTML 소스 준비
5. 스텝별 검수, 사용자 직접 수정, 피드백 재실행, 에이전트 질문 응답
6. 승인한 결과로 다음 스텝 진행; 검수 지점에서 전체 자동 진행을 일시 대기
7. 제작 세션 생성 시 전체 구성·설정·모델을 고정하고 세션별 결과·대화·승인·진행을 보존
8. 모든 스텝 완료·검수 후 출력 탭에서 최종 결과 미리보기·다운로드

SVG/HTML은 `sandbox`와 CSP를 적용한 iframe에서 미리 본다. 서버에서 코드를 실행하거나 프레임을 녹화·인코딩하지 않는다. 실제 파일은 소유권을 검사해 스텝 결과에 연결할 수 있다. 문서·코드는 해당 형식으로 내려받고 실제 미디어만 재생·다운로드한다. 기존 준비 패키지 API는 호환성을 위해 보존하지만 출력 화면에는 노출하지 않는다.

### 화면 탐색

- 왼쪽 메뉴는 제작 스튜디오·연결·모델 실행·작업 기록의 전역 탐색이다. 상단에서 전역 메뉴를 반복하지 않는다.
- 스튜디오 상단 탭은 목표·모델, 스텝 구성, 제작, 출력이다. 프로젝트 선택·구성 버전·구성 저장은 공통으로 유지한다.
- 기본 에이전트는 목표·모델, 스텝별 재정의는 스텝 구성에서 편집한다. 계획 제안 대화와 결과 피드백 대화의 입력 초안을 분리한다.
- 스텝 추가·삭제·연결·검수 옵션은 스텝 구성, 세션 생성·실행·결과·버전·직접 수정·승인은 제작, 최종 결과 미리보기·다운로드는 출력에 둔다. 출력 탭에서 제작 흐름이나 형식 폼을 다시 조립하지 않는다.
- 탭 이동과 연결 관리 방문은 미저장 편집을 버리지 않는다. 저장된 데이터는 계속 서버 SQLite가 소유하며, 새로고침 전 미저장 편집은 사용자가 저장해야 한다.
- 하위 탭은 키보드 좌우 화살표·Home·End로 이동한다. 연결 화면에 불필요한 탭을 만들지 않으며, 모델 실행은 유형별 탭, 작업 기록은 종류별 탭을 사용한다.
- 프로젝트 제목 클릭으로 이름을 수정한다. Enter/체크로 저장, Esc로 취소하며 빈 이름과 동시 변경 충돌을 표시한다. 이름 변경은 별도 metadata 작업으로 계획 revision·준비 결과·대기 작업을 변경하지 않고 다른 미저장 설정을 저장하지 않는다.
- 빈 스텝 안내의 계획 제안은 계획 대화 입력으로 이동한다. 스텝 직접 추가는 새 스텝을 만들고 이름 입력에 포커스를 둔다. 안내 클릭만으로 모델을 호출하지 않는다.
- 스텝이 없을 때는 목록·빈 편집기를 펼치지 않고 짧은 시작 안내와 넓은 제작 대화를 배치한다. 스텝 추가 후 목록·설정·대화의 세 영역으로 전환한다.
- 대화는 Markdown 문단·목록·표·코드를 렌더링하며 원시 HTML과 위험한 링크는 실행하지 않는다. 기술 이름·반복 발신자 표시를 생략하고 작업 이벤트는 접은 기록으로 분리한다. 대화와 제안은 하나의 스크롤 영역을 공유하고 입력창은 아래에 유지한다.
- 반복 사용량 체크박스 대신 제안·준비 버튼 클릭 또는 Ctrl/⌘Enter가 사용자 실행 요청을 확정한다. 기존 서버의 명시적 요청 검사는 유지한다. 화면 진입·입력·설정 저장으로는 모델을 호출하지 않는다.

### 이번 영상과 공통 제작 설정

- 목표·모델의 **제작 기본값**은 새 세션에 사용할 기본 안내·길이·비율·참조·모델을 편집한다. 이번 편의 주제·개별 자료는 새 제작에서 입력한다.
- **공통 제작 설정**에는 브랜드·시청자·말투·시각 스타일·제작 방식·음성 방향·선택적 예산 제한·제작 모델 참조·공통 이미지/로고를 둔다. 지정하지 않은 선택 항목을 필수 설문으로 만들지 않는다. 계정 비밀값은 포함하지 않는다.
- 설정을 이름으로 저장·불러오고 새 영상 생성 시 선택할 수 있다. 프로젝트에는 설정의 사본을 저장한다. 저장 설정을 갱신해도 기존 영상에는 자동 적용하지 않으며 설정 revision 충돌과 워크스페이스 접근 권한을 검사한다.
- **새 제작**은 새 ID·목표와 시작 구성 revision을 사용한다. 모든 스텝·연결·공통 설정·규격·참조·선택 모델 카탈로그와 endpoint를 서버에서 복사해 고정한다. 인증 토큰은 복사하지 않고 같은 계정 참조의 현재 인증을 사용한다. 이후 스텝 예약도 세션의 모델 스냅샷을 사용한다.
- 참조 이미지는 기존 파일 업로드·비공개 제공 경로를 사용한다. 공통/개별을 합쳐 중복 제거 후 최대 6개·20MB이며 서버에서 소유권을 검사한다. 이미지 입력 지원이 선언된 모델에는 실제 이미지를 전달하고, 텍스트 전용 모델에는 사용 목적·메타데이터만 전달한다. 이미지 내용을 본 것처럼 추정하지 않도록 입력 전달 방식도 알린다.
- 준비 작업은 설정·영상 규격·참조 메타데이터와 관련 대화 최대 최근 16개/48,000자를 스냅샷으로 보존한다. 이전 질문과 답변을 함께 전달한다. 원본 설정 변경은 기존 세션에 전파하지 않고, 세션 내부 결과 변경만 같은 세션의 후속 결과를 갱신 필요로 표시한다.
- 새 계획 도구는 `scope: single-video`를 요구한다. 구성 단계에서는 미래 세션의 주제를 받는 재사용 과정을 제안하고 구체적인 에피소드 주제를 필수로 묻지 않는다. 실제 제작에서 진행을 막는 정보만 짧게 질문한다. 실제 모델의 의미적 계획 품질은 별도 계정 호출 검증 대상이다.
- 기존 원본은 보존한다. 이전 실행·결과가 있는 프로젝트는 기존 제작 세션을 한 번 만들고 작업 참조도 해당 세션으로 이전한다. 원본 기록·해시·승인·버전을 보존하며 이미 진행 중인 작업의 로그·결과·복구도 세션으로 이어진다.

### 출력물 조회

- 최종 표시 스텝(`finalOutput`)이 있으면 그 결과, 없으면 후속 연결이 없는 마지막 스텝 결과를 사용한다. 출력 대상과 형식은 제작 과정의 결과로 결정하며 별도 출력 라우팅 폼은 없다.
- 세션의 모든 스텝이 완료돼야 현재 승인 버전의 최종 결과가 출력된다. 진행 중이면 대기·검수 스텝과 이어가기만 표시한다. 서버 다운로드 조회도 완료·최신 승인·최종 스텝·세션 소유권을 검사한다.
- 문서/코드 다운로드는 실제 내용과 확장자를 사용한다. 결과의 `assetIds`는 서버 소유권 검사를 거쳐 저장하며 이미지·영상·음성 파일을 미리 보고 다운로드한다. 참조 이미지를 제작한 결과로 자동 취급하지 않는다.

### 공통 UI 구조

- Tailwind CSS 4 + shadcn/ui의 소스 소유 방식으로 구현하며 Radix의 Dialog/Popover/Tooltip/Collapsible/Slot을 사용한다. `apps/client/components.json`에 alias와 스타일 진입점을 기록한다.
- `components/ui`: Button, Input, Textarea, NativeSelect, Card, Badge, Label, Checkbox, Dialog, Popover, Tooltip, Collapsible. 기본 입력·주요 버튼은 44px, 보조 버튼은 36px로 통일한다.
- `components/studio`: Panel, SectionHeader, FormSection, FormField, ActionBar, HelpText, EmptyState, Notice, IconButton, InlineAction, EditableTitle, ProjectSwitcher, StatusBadge. 제작 패널과 연결 화면에서 재사용한다.
- 패널 안쪽 간격은 기본 24px·좁은 화면 16px, 폼 간격은 16px, 레이블과 입력은 8px를 기준으로 한다. 본문 입력 16px, 버튼·레이블 14px, 보조 정보 최소 12px를 유지한다.
- `app/styles.css`에서 theme/base/legacy/components/utilities 순서로 CSS layer를 선언한다. 기존 실행 화면의 스타일과 새 공통 UI를 함께 유지하고, `production.css`는 제작 화면의 배치·스크롤·반응형 구성에 집중한다.
- `components/ai-elements`의 Conversation/Message/ToolEvent/Plan/PromptInput은 공식 Chat/Plan 패턴을 Pi 데이터에 맞춘 자체 구현이다. 대화 스크롤·새 메시지 이동, 접을 수 있는 제안, 도구 이벤트, Ctrl/⌘Enter 입력을 제공한다. Vercel AI SDK나 `useChat`을 도입하지 않는다.
- 대화상자는 포커스를 내부에 유지하고 닫으면 호출한 컨트롤로 돌려준다. 제목 편집 종료도 제목 버튼으로 포커스를 복원한다.

직접 영상/이미지/음성 스텝에 선택한 생성 모델은 이후 실제 제작을 위한 계정 참조다. 준비 실행은 텍스트 에이전트만 호출한다. 실제 생성 어댑터를 노출하는 도구는 Pi에 등록하지 않는다.

## 실행·검수 모델

- 스텝은 목표·종류·지시·입력 스텝 ID·검수 옵션·에이전트 재정의·향후 생성 모델 참조를 가진다.
- 목록 순서는 준비 작업 선택 순서이고, 실행 선행 조건은 입력 연결이다. 삭제된 입력과 순환 연결을 표시하고 실행을 거부한다.
- 상태: 대기 → 실행 대기 → 준비 중 → 검수 필요/응답 필요 → 준비 완료. 오류는 실패, 입력·설정 변경은 갱신 필요로 구분한다.
- 검수 대기 중에는 다음 스텝을 예약하지 않는다. 승인은 최신 결과 ID·현재 지시 해시·입력 결과 버전을 검사하고 중복 승인으로 후속 작업을 중복 생성하지 않는다.
- 결과 수정은 새 버전을 만든다. 이전 결과·승인·피드백은 보존하고 후속 결과는 갱신 필요로 표시한다.
- 계획 저장은 revision 기반으로 충돌을 확인한다. 에이전트 제안은 기반 revision이 바뀌었으면 기존 사용자 편집을 덮어쓰지 않는다.
- 세션의 정의는 시작 시 고정되고 HTTP API에서 변경을 거부한다. 원본 구성 변경은 세션의 실행 중·대기 작업·결과·승인을 변경하거나 취소하지 않는다. 이전 비세션 작업의 호환 경로만 기존 갱신 규칙을 유지한다.
- 실행·검수·직접 수정·피드백 API에는 세션이 필요하다. 계획 대화는 원본에, 제작 대화·결과·진행·중복 요청 검사는 각각의 세션에 귀속된다.
- 실행 중 피드백은 DB에 저장한다. Pi의 다음 요청 준비에서 전달하고 미반영 피드백이 있는 동안 도구 결과 제출을 막는다.

## 서버·Pi 통합

`@earendil-works/pi-agent-core`와 `pi-ai` 1.5.2를 server 내부에서 사용한다. Pi CLI의 전역 인증 파일·기본 셸 도구·파일 도구는 사용하지 않는다. OpenStudio가 선택 계정의 키/토큰을 서버에서 주입하고 기존 OpenAI 토큰 갱신 경로를 재사용한다.

등록 도구는 다음뿐이다.

- `propose_workflow`: 편집 가능한 구조화 계획 제안
- `submit_result`: 원고·설계·소스 코드 제출
- `ask_user`: 필수 정보가 없으면 질문 후 대기

단계 전환과 승인은 OpenStudio 서버가 담당한다. Pi에는 이를 우회하는 도구가 없다. 한 작업의 모델 요청은 최대 6턴, 전체 실행 시간은 120초로 제한하며 SDK의 자동 요청 재시도는 끈다. 한 제작 세션의 에이전트 작업은 동시에 하나만 실행한다. 원본 계획 대화는 별도이며 서로 다른 제작 세션은 독립적으로 진행할 수 있다.

Pi 통신은 현재 OpenAI Responses(Sign in with ChatGPT 포함), OpenAI-compatible Completions, Anthropic Messages, Google Generative AI로 매핑한다. 일반 텍스트 호출 성공과 Pi 도구 호출 성공은 별개이며 실제 계정 권한·모델 지원은 호출에서 확인해야 한다. 단가가 없는 모델의 비용을 무료로 표시하지 않는다.

## 영속성

프로젝트·제안·결과·검수·피드백·준비 작업을 기존 암호화 Workspace에 저장한다. `workflow:<task ID>`를 기존 SQLite 작업 인덱스에 함께 반영하고 server 내부 루프가 처리한다.

- 브라우저는 상태 GET만 요청한다. 닫아도 준비 작업을 계속한다.
- 대기 작업은 재시작 후 실행한다.
- 도구 결과를 이미 커밋한 작업은 추가 모델 호출 없이 복구한다.
- 모델 응답을 확인하지 못한 실행 중 작업은 `unknown`으로 보존하며 자동으로 재요청하지 않는다.
- 검수 대기는 완료된 준비 작업과 프로젝트 상태로 저장하므로 프로세스나 네트워크 요청을 붙잡고 있지 않는다.

## 다음 확장

실제 제작 도구를 점진적으로 추가한다. 준비 명세에서 기존 생성 작업을 제출하고, 반환 에셋을 결과로 연결하고, 브라우저 프레임 렌더러·FFmpeg 합성·다중 출력 렌더링을 연결한다. 현재 명세 결과를 실제 에셋 생성 성공으로 취급하지 않는다.
